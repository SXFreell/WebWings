# 独立扩展设置页设计

## 目标

将所有设置从会自动关闭的浏览器扩展弹窗迁移到持久的 Chrome 扩展设置页。用户从弹窗点击“设置”后进入独立页面，并能在首次绑定期间完成备份下载、凭证记录与同步策略选择，而不会因系统保存对话框关闭弹窗而丢失进度。

## 范围

- 新建 `options.html`，并在 Manifest V3 中通过 `options_ui` 注册独立设置页。
- 扩展 Vite 构建新增 settings entry point；入口根据页面加载 popup 或设置页应用。
- popup 移除内嵌的设置内容。左下角“设置”按钮调用 `chrome.runtime.openOptionsPage()`；在非扩展环境中不执行该调用。
- 设置页承载现有全部设置：云同步连接、可恢复的首次绑定协调、管理员 Key 管理、全量导入、全量导出和数据统计。
- 设置页独立读取 IndexedDB 中的收藏夹数据，并持有导入对话框所需的目录列表与导入目标；不依赖 popup 的 React 状态。

## 页面与数据流

1. 用户在 popup 点击“设置”。
2. Chrome 打开或聚焦扩展设置页；popup 可正常关闭。
3. 设置页读取本地收藏与同步绑定/首次绑定会话，渲染与现有设置页等价的内容。
4. 首次绑定调用现有 `prepareBackup()`、`submitBackupProof()` 和 `completeFirstBind()`。下载 ZIP 时设置页保持打开；完成下载后，持久化的会话进入 `backup_downloaded`，可继续下一步。
5. 本地变更通知仍触发设置页刷新，保证导入、绑定完成和后台同步状态的显示一致。

## 约束与错误处理

- 不尝试阻止浏览器关闭 popup：这是 Chrome 的既定行为。
- 不改变备份完成的安全条件。只有 `chrome.downloads` 报告完成后才记录备份成功并允许提交凭证。
- 现有的可恢复 `BindSessionRecord` 继续作为唯一的首次绑定进度来源；页面重开时从 IndexedDB 重新加载。
- 如果 `openOptionsPage()` 不可用，popup 保持可用但不显示内嵌设置，避免假装成功；在已支持的 Chrome 版本中该 API 可用。

## 测试与验收

- 单元测试验证 popup 的设置操作请求打开扩展设置页。
- 渲染测试验证设置页显示同步设置和数据管理，并从 IndexedDB 读取统计与目录。
- 构建测试确认 `options.html` 与对应资产输出，Manifest 指向有效设置页。
- 手工验收：从 popup 打开设置页，发起首次绑定并在保存备份后回到设置页，确认无需再次下载即可继续“记录备份凭证”。
