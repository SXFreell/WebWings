## Context

参见 `proposal.md` 的动机。当前应用将目录树、收藏列表、弹窗和数据管理逻辑集中在 `src/App.tsx`；IndexedDB 通过 `src/lib/bookmarks-db.ts` 访问。右侧尚无页面状态，目录菜单使用 `side="right"`，导入使用清空后重写全部节点的事务。

本次变更跨越工作区导航、列表排序与 IndexedDB 批量迁移，且目录级导出需要生成脱离原父目录仍然有效的自包含数据，因此需要明确的数据边界与事务设计。

## Goals / Non-Goals

**Goals:**

- 保持旧项目的 220px 左侧栏加 540px 主内容区布局，不引入完整路由系统。
- 将收藏视图、设置视图和数据传输对话框拆成职责清晰的组件。
- 让同一份导出文件可以安全、重复地合并到任意目标目录。
- 保持现有 WebWings JSON v1 文件可导入，并保留历史时间以支持时间排序。
- 所有批量数据变更具备原子性和可测试性。

**Non-Goals:**

- 不实现云同步、浏览器原生书签同步、拖拽排序或重复链接合并。
- 不为设置页增加主题、外观或其他偏好设置。
- 不改变 IndexedDB schema 版本、浏览器权限或扩展 Manifest。
- 不把“未分类”视为可承载子目录的真实目录。

## Decisions

### 1. 使用轻量视图状态而不是新增 React Router

应用维护 `activeView: 'bookmarks' | 'settings'`，现有 `selected` 继续表示收藏范围。点击设置只切换 `activeView`；点击任意收藏范围同时更新 `selected` 并切回 `bookmarks`。左侧目录树始终挂载，因此设置页不会破坏展开状态。

选择该方式是因为扩展只有两个主视图，无 URL 深链需求。引入路由会增加依赖和状态同步成本，收益有限。

### 2. 将目录菜单改为下方、右对齐的 Radix 定位

目录行菜单继续使用已有 shadcn/Radix Dropdown Menu，但配置为 `side="bottom"`、`align="end"`，并设置适当的 `sideOffset` 与 `collisionPadding`。触发按钮继续通过 `asChild` 传给 Radix，并保持 `event.stopPropagation()`，避免点击菜单时切换目录。

相比手写绝对定位，Radix 能在滚动容器和视口边缘执行碰撞检测；相比当前向右展开的配置，该方案符合菜单出现在三个点下方的预期。

### 3. 排序配置独立于收藏节点并保存在 localStorage

定义五个稳定排序值：`default`、`timeAsc`、`timeDesc`、`titleAsc`、`titleDesc`。通过小型 hook 从 `webwings:bookmark-sort` 读取并保存配置，无法识别的旧值回退为 `default`。

收藏列表的数据流固定为“按当前范围筛选 → 按关键词筛选 → 复制数组并排序”。默认排序按 `order` 降序；时间排序使用 `createdAt`；标题排序使用中文环境的 `Intl.Collator`。为保证稳定结果，主比较值相同时依次回退到 `order` 和 `id`。

排序配置不写入 IndexedDB，因为它是界面偏好而非收藏数据；也不应用于目录树，以免改变现有目录行为。

### 4. 导出层生成副本，不修改数据库节点

数据层增加两个导出查询：

- 全量导出：复制全部节点并直接生成 v1 payload。
- 目录导出：从当前目录的直接子节点开始收集全部后代；复制节点，并将直接子节点的 `parentId` 改为 `null`。

当前目录节点本身不进入文件。这样导出结果符合现有 v1 校验规则，是一个没有外部父引用的自包含森林；导入到目标目录时不会额外嵌套一层同名目录。

曾考虑把当前目录本身作为单根节点导出，但导入到当前目录会得到“目标目录/原目录名/内容”的额外层级，与“导入到当前目录”的直觉不符。

### 5. 导入使用两阶段转换和单事务合并

导入流程分为纯函数准备阶段和数据库写入阶段：

1. 使用现有格式校验确认节点唯一、父引用完整、无循环且书签 URL 安全。
2. 为文件中的每个节点生成新 ID，形成 `oldId -> newId` 映射。
3. 克隆每个节点：若原 `parentId` 在映射中，则替换为映射后的父 ID；若为 `null`，则替换为目标目录 ID 或 `null` 根目录。
4. 保留标题、URL、favicon、`createdAt` 和 `updatedAt`。顶层节点的 `order` 从目标目录现有最大值之后开始，并保持原有相对顺序；内部节点保留其相对顺序。
5. 在一个 `readwrite` 事务中批量 `add` 所有新节点，不再调用 `clear()`。

目标目录必须在准备阶段确认仍然存在且类型为 folder。所有 ID 都重新生成，因此重复导入同一文件不会覆盖已有节点。使用 `add` 而非 `put` 可在意外碰撞时让事务失败并整体回滚。

曾考虑只在 ID 冲突时重命名，但这会让导入结果取决于目标库状态，也无法满足全部条目更新 ID 的要求。

### 6. 设置页和目录页共用导入对话框

新增一个受控数据导入对话框，接收可选的锁定目标目录：

- 设置页打开时目标可选，选项为根目录和全部现有目录。
- 目录页打开时目标锁定为当前目录，不重复显示目标选择器。

对话框展示选中文件、目标路径、校验或写入错误以及确认按钮。成功后统一重新加载节点并显示导入数量；失败时保留现有数据和对话框上下文。

设置页的“导出全部”直接调用全量导出。收藏页右上角菜单仅在选中真实目录时展示“导出当前目录”和“导入到当前目录”。

### 7. 按组件边界拆分当前 App

在不进行无关重构的前提下，建议拆出：

- `FolderTree`：目录渲染和行操作菜单。
- `BookmarksView`：标题、搜索、排序、目录级操作和收藏列表。
- `SettingsView`：设置页数据管理区。
- `ImportDialog`：文件选择、目标目录和导入提交。
- `lib/bookmark-transfer`：范围收集、payload 创建与 ID 重映射纯函数。

`App` 只保留节点加载、视图选择和跨组件动作协调。这样范围导出和 ID 重映射可以脱离浏览器 UI 做单元测试。

## Risks / Trade-offs

- [大量节点导入需要一次性读取和克隆整个文件] → 在对话框读取阶段限制文件为 JSON，先校验再开启事务，并保持错误提示；当前扩展定位为本地个人收藏夹，不引入流式解析复杂度。
- [目录在打开导入对话框后被删除] → 提交前重新从数据库验证目标目录，失效时中止导入。
- [保留历史时间导致新导入条目在时间排序中不一定置顶] → 这是时间排序的预期语义；默认排序仍通过追加后的 `order` 体现新导入位置。
- [Radix 碰撞检测可能在空间极端不足时翻转菜单] → 允许为保持可见而调整，但始终绑定触发按钮并通过浏览器视觉测试防止回到左上角。
- [从覆盖导入改为合并导入改变现有行为] → 设置页明确显示目标目录和“合并导入”说明，不再展示会覆盖全部数据的确认文案。

## Migration Plan

1. 先增加并测试纯函数导出范围、ID 重映射和批量合并 API，保留旧 `replaceAllNodes` 供现有测试过渡。
2. 增加排序配置和收藏视图排序 UI，不改变现有节点结构。
3. 增加设置视图及共用导入对话框，将入口和目录上下文操作接入新数据 API。
4. 验证新旧 v1 导出文件均可合并导入后，移除 UI 对 `replaceAllNodes` 的调用；未使用的旧函数可在同次变更中删除。
5. 回滚时恢复旧 UI 入口和旧导入调用即可；由于 IndexedDB schema 未迁移，现有数据无需回滚转换。
