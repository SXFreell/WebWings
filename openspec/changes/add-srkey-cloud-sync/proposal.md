## Why

WebWings 当前仅将收藏数据保存在单个浏览器的 IndexedDB 中，无法在多台设备之间持续保持一致。需要在不引入传统用户体系的前提下，以用户提供的同步服务地址和 `srkey` 建立独立数据空间，并提供本地优先、实时、可离线恢复的云端同步能力。

## What Changes

- 增加独立的 WebWings 同步服务，使用服务实例 ID、单调递增事件序列、快照和实时通知协调多设备数据。
- 使用 `Server URL + srkey` 作为首次连接凭据；插件先验证服务兼容性和目标 Origin 权限，再提交 `srkey` 绑定设备。
- 取消传统用户、账号和密码概念；每个 `srkey` 映射到一个完全隔离的数据空间，同一 Key 可供多台设备同时使用。
- 服务端首次启动时创建默认管理员 Key。管理员可在插件中创建、撤销、删除和轮换普通 Key，但不能通过管理权限读取其他 Key 的收藏内容。
- 管理员 Key 遗忘时允许服务器运维者通过数据库维护流程重置 Key，并保持管理员自己的数据空间不变；服务端不依赖可公开读取的明文 Key。
- 首次绑定前强制导出包含云端和本地全部收藏数据的安全备份。云端为空时使用本地数据初始化；云端已有数据时，用户必须选择使用云端、使用本地或无损合并。
- 引入本地 outbox、服务端幂等操作、按数据空间排序的事件日志、WebSocket 增量通知和断线补拉，使本地操作立即生效并在在线设备间即时传播。
- 为并发修改、移动、级联删除、批量导入和排序定义确定性冲突规则，并使用软删除、同步 epoch 和版本条件防止旧设备复活已删除或已替换的数据。
- 增加连接、离线、权限拒绝、Key 撤销、服务实例变化、快照过期和首次绑定中断等恢复流程。

## Capabilities

### New Capabilities

- `srkey-access-management`: 定义默认管理员 Key、普通 Key 生命周期、设备凭证、数据库恢复和每 Key 数据隔离规则。
- `sync-server-connection`: 定义 Server URL 校验、服务发现、动态主机授权、Key 绑定、连接身份和换服/换 Key 行为。
- `initial-sync-reconciliation`: 定义首次绑定的云端与本地强制备份、版本锁，以及使用云端、使用本地或合并三种处理路径。
- `realtime-bookmark-sync`: 定义本地优先写入、幂等增量同步、实时通知、离线恢复、冲突解决和服务端快照行为。

### Modified Capabilities

无。当前 `openspec/specs` 中没有已归档的主规格，本变更只新增能力。

## Impact

- 插件需要增加 Manifest V3 后台 Service Worker、动态主机权限、连接与 Key 管理界面、绑定向导、同步状态以及 IndexedDB 同步元数据和 outbox。
- 现有收藏 CRUD 与批量导入需要通过可原子记录本地变更和待发送操作的数据访问边界执行，现有导出格式需要扩展为可校验的绑定安全备份格式。
- 新增服务端 HTTP API、WebSocket 网关、Key/设备认证、PostgreSQL 权威状态、事件日志、快照、软删除和清理任务。
- 部署方需要配置公开的 HTTPS Server URL、数据库和管理员 Key 初始化或恢复方式；本机开发可使用受限的 localhost HTTP 地址。
- 现有纯本地收藏在用户主动绑定前继续可用；启用云同步后，同一个活动连接由服务实例 ID 和 Key ID 唯一确定。
