## Purpose

定义以高熵 `srkey` 替代传统用户账号的访问模型，使每个 Key 拥有隔离的同步数据空间，并让默认管理员能够安全管理 Key、设备凭证和失钥恢复。

## ADDED Requirements

### Requirement: 每个 srkey 标识一个独立数据空间
系统 MUST 将每个有效 `srkey` 映射到稳定的内部 Key 标识和唯一数据空间，并使同一 Key 绑定的设备共享该空间。不同 Key 的节点、事件、快照、游标和实时通知 MUST 相互隔离。

#### Scenario: 同一个 Key 绑定多台设备
- **WHEN** 两台设备使用同一 Server URL 和同一有效 `srkey` 完成绑定
- **THEN** 两台设备获得同一个数据空间的访问权限
- **AND** 两台设备使用各自独立的设备凭证

#### Scenario: 不同 Key 使用相同节点 ID
- **WHEN** 两个不同 Key 的数据空间包含相同节点 ID
- **THEN** 系统分别保存并返回各自的数据
- **AND** 任一 Key 的请求或实时订阅不得暴露另一个 Key 的数据

### Requirement: 服务端必须提供默认管理员 Key
系统 MUST 在首次初始化时创建或接收一个默认管理员 Key。管理员 Key SHALL 同时拥有自己的独立同步数据空间和 Key 管理权限，但管理权限不得授予读取其他 Key 收藏内容的能力。

#### Scenario: 首次启动未配置管理员 Key
- **WHEN** 服务端首次启动且数据库中不存在管理员 Key
- **THEN** 系统生成一个高熵管理员 `srkey`
- **AND** 仅在首次初始化输出中展示一次完整值
- **AND** 为该 Key 创建独立数据空间

#### Scenario: 重启已有服务端
- **WHEN** 服务端启动且数据库中已存在管理员 Key
- **THEN** 系统继续使用现有管理员身份
- **AND** 不得额外生成新的默认管理员 Key

#### Scenario: 管理员访问其他 Key 的收藏接口
- **WHEN** 管理员凭证请求读取某个普通 Key 的收藏数据
- **THEN** 系统拒绝该请求
- **AND** 管理员仍可读取该 Key 的标签、状态、设备数和数据量等管理元数据

### Requirement: 管理员必须能够管理普通 Key
绑定管理员 Key 的插件 SHALL 允许管理员列出、创建、撤销、删除和轮换普通 Key。新建 Key MUST 获得新的内部 Key 标识和空数据空间，完整 `srkey` MUST 只在创建或轮换成功时展示一次。

#### Scenario: 创建普通 Key
- **WHEN** 管理员提交可选标签创建普通 Key
- **THEN** 系统生成新的高熵 `srkey` 和独立数据空间
- **AND** 向当前管理员展示一次完整 Key
- **AND** 后续列表仅显示标签、Key 前缀、状态和管理元数据

#### Scenario: 轮换普通 Key
- **WHEN** 管理员轮换一个现有普通 Key
- **THEN** 系统保留原内部 Key 标识及其全部数据
- **AND** 使旧 `srkey` 和旧设备凭证失效
- **AND** 展示一次新的完整 `srkey`

#### Scenario: 管理员尝试删除唯一管理员 Key
- **WHEN** 管理员在插件中尝试删除当前唯一管理员 Key
- **THEN** 系统拒绝操作
- **AND** 提示通过管理员恢复流程进行轮换

### Requirement: 删除 Key 必须立即撤销访问并延迟清理数据
系统 MUST 在删除 Key 时立即撤销其访问能力、设备凭证和实时连接，并将数据空间标记为待删除。系统 SHALL 在可配置的保留期后永久清理该数据空间，默认保留期为 30 天。

#### Scenario: 删除正在使用的普通 Key
- **WHEN** 管理员删除一个已绑定多台设备的普通 Key
- **THEN** 服务端立即拒绝该 Key 及其全部设备凭证的新请求
- **AND** 关闭该数据空间的实时连接
- **AND** 将数据空间标记为待删除而非立即物理清除

#### Scenario: 保留期内恢复 Key
- **WHEN** 管理员在数据清理前恢复一个待删除 Key
- **THEN** 系统取消待删除状态并生成新的 `srkey`
- **AND** 保留原内部 Key 标识和数据空间
- **AND** 不恢复任何旧设备凭证

#### Scenario: 保留期届满
- **WHEN** 待删除 Key 的保留期届满且未被恢复
- **THEN** 系统永久清理其节点、事件、快照、设备和 Key 记录

### Requirement: srkey 必须安全验证和展示
`srkey` MUST 具备不可猜测的密码学随机性。服务端 MUST 使用不可直接还原原值的验证材料保存 Key，不得在请求日志、错误消息或管理列表中记录完整 Key，并不得通过不同错误暴露 Key 是否存在。

#### Scenario: 验证有效 Key
- **WHEN** 客户端通过加密连接提交有效 `srkey`
- **THEN** 服务端以恒定时间语义验证 Key
- **AND** 不在常规日志中记录完整 Key

#### Scenario: 提交无效或已撤销 Key
- **WHEN** 客户端提交不存在、格式错误或已撤销的 `srkey`
- **THEN** 服务端返回统一的绑定失败结果
- **AND** 不透露失败 Key 是否曾经存在或其角色

### Requirement: 绑定后必须使用可撤销设备凭证
系统 MUST 仅在设备首次绑定或重新绑定时接收原始 `srkey`，成功后为设备签发短期访问凭证和可撤销的续期凭证。插件 MUST 在完成绑定后清除原始 `srkey`，后续同步不得依赖本地保存完整 Key。

#### Scenario: 成功绑定设备
- **WHEN** 设备使用有效 `srkey` 完成绑定
- **THEN** 服务端注册独立设备身份并签发设备凭证
- **AND** 插件仅持久化服务信息、Key 前缀、设备身份和续期凭证

#### Scenario: Key 被轮换
- **WHEN** 管理员轮换一个 Key
- **THEN** 该 Key 已签发的全部设备凭证立即失效
- **AND** 设备必须使用新 `srkey` 重新绑定

### Requirement: 管理员失钥后必须能够通过数据库维护恢复
系统 MUST 提供受控的数据库维护流程，使服务器运维者无需知道原管理员 `srkey` 即可替换其验证材料。恢复 MUST 保持管理员内部 Key 标识和数据空间不变，并撤销全部旧管理员设备凭证。

#### Scenario: 重置遗忘的管理员 Key
- **WHEN** 运维者通过受控维护流程为现有管理员设置新的高熵 `srkey`
- **THEN** 旧管理员 Key 和旧设备凭证立即失效
- **AND** 新 Key 可以绑定并继续访问原管理员数据空间
- **AND** 普通 Key 及其数据空间不受影响
