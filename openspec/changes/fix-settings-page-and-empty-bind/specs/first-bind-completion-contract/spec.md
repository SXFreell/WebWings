## Purpose

定义首次绑定完成请求从本地快照到服务端提交的可验证协议契约，确保空数据初始化可成功完成，并为无效请求提供安全且可定位的错误信息。

## ADDED Requirements

### Requirement: 绑定完成请求必须在发送前符合共享协议
客户端 MUST 从已持久化的绑定会话和用户选择的策略构造完整绑定请求，并在网络发送前使用与服务端一致的协议规则验证最终请求。

#### Scenario: 构造合法绑定完成请求
- **WHEN** 备份凭证已记录且用户选择一个允许的协调策略
- **THEN** 请求包含协议版本、非空操作 ID、策略、本地节点数组以及预期云端序列、同步 epoch 和本地修订号
- **AND** 通过共享协议验证后才发送到服务端

#### Scenario: 持久化会话缺少必需字段
- **WHEN** 客户端无法从绑定会话构造符合协议的完成请求
- **THEN** 客户端不得发送该请求
- **AND** 页面显示说明请求数据无效并要求重新开始绑定的中文错误
- **AND** 本地收藏、当前活动绑定和已下载备份保持不变

### Requirement: 空数据空间必须能够完成初始化
当锁定的云端快照和本地快照均为空时，系统 SHALL 接受空本地节点数组作为合法的 `initialize_cloud` 请求，并建立可用的活动绑定。

#### Scenario: 空云端和空本地初始化成功
- **WHEN** 用户已完成两个空快照的备份及凭证记录并选择“初始化云端”
- **THEN** 客户端提交包含空本地节点数组的合法绑定完成请求
- **AND** 服务端原子创建已初始化的空数据空间
- **AND** 客户端保存设备会话、同步 epoch 和服务端游标并清除首次绑定会话

#### Scenario: 空数据初始化失败
- **WHEN** 空数据初始化请求因协议或服务端错误被拒绝
- **THEN** 系统不得创建半完成的活动绑定
- **AND** 本地数据和已下载备份保持不变
- **AND** 用户获得可重试或重新绑定的明确提示

### Requirement: 协议校验失败必须提供安全诊断
服务端 MUST 对无效绑定完成请求返回稳定的通用错误代码，同时记录足以定位失败字段的脱敏诊断信息。诊断信息 MUST NOT 包含 `srkey`、授权头、bind token、设备令牌或收藏内容值。

#### Scenario: 服务端收到无效完成请求
- **WHEN** 绑定完成请求缺少字段或字段类型不符合协议
- **THEN** 服务端返回 `invalid_bind_request` 客户端错误
- **AND** 服务端日志记录端点、校验失败字段路径和错误类别
- **AND** 日志不记录请求字段值或任何凭据

#### Scenario: 客户端收到通用无效请求错误
- **WHEN** 已通过本地校验的绑定完成请求仍被服务端以 `invalid_bind_request` 拒绝
- **THEN** 客户端提示服务端协议不兼容或版本不一致并要求重新连接或更新服务
- **AND** 不向用户展示凭据或原始请求正文
