## Purpose

定义设备首次绑定数据空间时的可恢复协调流程，确保用户在创建、覆盖或合并任何一侧数据前已经获得对应云端和本地完整备份，并且操作基于未变化的版本执行。

## ADDED Requirements

### Requirement: 首次绑定必须使用持久化协调会话
系统 MUST 为首次绑定创建可恢复的协调会话，记录服务实例 ID、Key ID、云端序列、同步 epoch、本地修订号、备份摘要、流程状态和过期时间。插件关闭或后台被终止后 SHALL 能够继续未完成会话。

#### Scenario: 插件在备份后关闭
- **WHEN** 用户已生成备份但尚未选择数据策略时关闭插件
- **THEN** 插件下次打开后恢复到该协调会话
- **AND** 不重复执行已确认完成且版本仍有效的步骤

#### Scenario: 协调会话过期
- **WHEN** 用户在会话过期后尝试继续
- **THEN** 系统废弃旧版本锁和备份确认状态
- **AND** 要求重新读取两侧数据并导出新备份

### Requirement: 任何初始化策略前必须导出云端和本地全部数据
系统 MUST 在创建云端数据、使用云端、使用本地或合并之前生成并成功下载一个安全备份包。备份 MUST 包含固定云端序列对应的全部活动及仍可恢复数据、当前本地全部收藏数据和可验证清单；即使一侧为空，也 MUST 包含合法的空数据文件。

#### Scenario: 云端为空但本地有数据
- **WHEN** 首次绑定发现云端没有收藏而本地存在收藏
- **THEN** 系统仍然导出合法的空 `cloud.json` 和完整 `local.json`
- **AND** 仅在浏览器确认备份下载完成后允许初始化云端

#### Scenario: 云端和本地均为空
- **WHEN** 首次绑定发现两侧均为空
- **THEN** 系统导出包含两个合法空数据文件的备份
- **AND** 随后创建空的已初始化数据空间

#### Scenario: 备份下载失败或被取消
- **WHEN** 浏览器报告备份下载失败或用户取消下载
- **THEN** 插件保持下一步操作禁用
- **AND** 不向任一侧写入或删除数据

### Requirement: 绑定备份必须可验证且不得包含凭据
安全备份包 SHALL 包含云端数据、本地数据和清单。清单 MUST 记录来源、服务实例 ID、Key 前缀、导出时间、云端序列、本地修订号、同步 epoch、节点数量和内容校验值。备份 MUST NOT 包含完整 `srkey`、设备续期凭证或访问令牌。

#### Scenario: 验证备份完整性
- **WHEN** 用户或恢复工具读取绑定备份包
- **THEN** 可使用清单中的校验值验证云端和本地数据文件
- **AND** 可确定每个文件对应的源版本和数据范围

#### Scenario: 检查备份敏感内容
- **WHEN** 绑定备份生成成功
- **THEN** 备份中不存在完整 `srkey`、访问令牌和设备续期凭证

### Requirement: 云端为空时必须使用本地数据初始化
当固定云端序列的有效数据为空时，系统 SHALL 在完成双备份后使用当前本地快照原子初始化该 Key 的云端数据空间。若本地也为空，系统 SHALL 初始化空数据空间。

#### Scenario: 使用本地收藏创建云端
- **WHEN** 云端为空、备份已完成且本地修订号未变化
- **THEN** 服务端原子写入本地完整节点树
- **AND** 返回新的同步 epoch、服务端序列和设备游标

#### Scenario: 初始化事务失败
- **WHEN** 上传、校验或服务端事务在初始化期间失败
- **THEN** 云端保持初始化前状态
- **AND** 本地数据和备份保持不变
- **AND** 用户可以重试当前会话

### Requirement: 云端有数据时必须让用户选择协调策略
当云端存在有效数据时，插件 MUST 在双备份完成后明确提供“使用云端”“使用本地”和“合并”三种互斥策略，并在用户选择前说明每种策略对两侧数据的影响。

#### Scenario: 备份完成前查看策略
- **WHEN** 云端存在数据但双备份尚未成功下载
- **THEN** 插件不得允许提交任何协调策略

#### Scenario: 用户取消首次绑定
- **WHEN** 用户在选择或应用策略前取消绑定
- **THEN** 本地和云端数据保持不变
- **AND** 候选连接不得替换当前活动连接

### Requirement: 使用云端必须安全替换本地数据
选择“使用云端”时，插件 MUST 在单个本地事务中使用备份对应的云端快照替换本地同步数据，移除未绑定到该云端版本的本地待发送操作，并在提交后拉取快照序列之后的新事件。

#### Scenario: 使用云端成功
- **WHEN** 用户选择使用云端且本地修订号与备份一致
- **THEN** 插件原子替换本地收藏树
- **AND** 从备份云端序列继续增量拉取
- **AND** 完成后启用实时同步

#### Scenario: 本地在备份后发生变化
- **WHEN** 应用云端快照前检测到本地修订号变化
- **THEN** 插件拒绝替换本地数据
- **AND** 要求重新导出两侧备份并重新确认策略

### Requirement: 使用本地必须原子重置云端同步 epoch
选择“使用本地”时，服务端 MUST 仅在云端序列、同步 epoch 和本地修订号与备份一致时原子替换云端数据。成功后 MUST 增加同步 epoch，使其他设备的旧游标和旧 epoch 操作失效。

#### Scenario: 使用本地成功
- **WHEN** 用户选择使用本地且两侧版本均与备份一致
- **THEN** 服务端以本地快照替换云端权威状态
- **AND** 增加同步 epoch 并发布重置事件
- **AND** 当前设备从新 epoch 开始同步

#### Scenario: 其他设备在备份后更新云端
- **WHEN** 应用本地快照前云端序列或 epoch 已变化
- **THEN** 服务端拒绝覆盖
- **AND** 插件要求重新导出云端和本地备份后再选择

#### Scenario: 旧设备提交旧 epoch 操作
- **WHEN** 另一设备在云端被重置后提交旧 epoch 的待发送操作
- **THEN** 服务端拒绝这些操作并要求该设备重新协调
- **AND** 不得让旧数据覆盖新 epoch 状态

### Requirement: 合并必须保留两侧数据并原子提交
选择“合并”时，系统 MUST 保留云端现有数据，并将不属于同一同步身份的本地节点树作为原子批次加入云端。系统不得根据标题或 URL 自动去重；发生 ID 冲突时 MUST 重映射冲突 ID 及其内部父引用，并保持目录结构和根节点相对顺序。

#### Scenario: 合并两个独立收藏树
- **WHEN** 用户选择合并且本地数据没有相同同步身份
- **THEN** 云端原有节点全部保留
- **AND** 本地节点树以新批次加入云端
- **AND** 相同 URL 或标题的不同节点均被保留

#### Scenario: 合并时发生节点 ID 冲突
- **WHEN** 本地节点 ID 与云端现有节点 ID 冲突但不属于同一同步身份
- **THEN** 系统为冲突的本地节点生成新 ID
- **AND** 使用同一映射更新其后代父节点 ID

#### Scenario: 合并批次校验失败
- **WHEN** 本地树包含无效父引用、循环目录或不安全 URL
- **THEN** 整个合并事务失败
- **AND** 云端和本地均保持合并前状态

### Requirement: 协调应用必须具备版本条件和幂等性
所有首次绑定应用请求 MUST 携带协调会话 ID、预期服务实例 ID、Key ID、云端序列、同步 epoch、本地修订号和唯一操作 ID。服务端 MUST 拒绝版本不匹配请求，并保证同一操作 ID 重试不会重复初始化、替换或合并数据。

#### Scenario: 网络中断后重试已成功操作
- **WHEN** 客户端未收到成功响应并使用相同操作 ID 重试
- **THEN** 服务端返回原操作结果
- **AND** 不重复创建或合并节点

#### Scenario: Key 在协调期间被撤销
- **WHEN** 管理员在首次绑定完成前撤销候选 Key
- **THEN** 服务端拒绝后续备份和应用请求
- **AND** 插件保留本地数据及已下载备份
